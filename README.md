# 市政采购公告档案

面向市政采购档案员的公告留存工具：输入公告号，从本地示范站采集招标公告正文与唯一附件，按站点修订号逐版留档。网站改稿、换附件、撤稿后，旧版仍可核对、下载。档案员还可维护全局敏感词表，把指定修订的标题与正文精确遮盖后生成可外发的脱敏公开页；词表一经有效改动，旧公开页立即失效。

技术栈：FastAPI + SQLite；Docker Compose 同时启动档案应用与可在浏览器改稿的本地示范站。

## 快速开始（Docker Compose）

```bash
docker compose up --build -d
```

- 示范站（可改稿/换附件/撤稿）：<http://localhost:8000>
- 档案采集应用：<http://localhost:8001>
- 健康检查：`curl -s http://localhost:8001/healthz`

首次启动示范站会写入两条示例公告（`ZFCG-2026-0001`、`ZFCG-2026-0002`）。在档案首页输入公告号即可采集。

停止并保留数据：`docker compose down`；同时删除数据卷：`docker compose down -v`。

## 本地运行（不使用 Docker）

## 使用流程

1. 打开档案首页，输入示范站上的公告号，点击“采集公告”。
2. 在示范站打开同一公告：
   - **改稿**：修改标题/正文并保存，站点修订号 +1；再次采集会新增存档版本。
   - **替换附件**：上传新附件，站点修订号 +1；再次采集会留存新附件，旧附件仍可下载。
   - **撤稿 / 恢复**：撤稿后站点对访客隐藏内容；再次采集只更新撤稿状态，不新建版本，历史版本仍可下载。
3. 档案公告页可查看版本历史、逐版正文与附件下载、采集/核对记录。

## 脱敏公开发布

1. 在档案应用的「敏感词表」页（`/words`）维护**全局**敏感词表：每行一个词，自动去空白、去重；上限 500 个词、每个不超过 200 字。
2. 打开某条公告的某个存档版本页，点击「按当前词表发布脱敏公开页」。系统按原文**精确（字面）匹配**遮盖标题与正文中的全部命中，多个词的重叠命中合并为连续遮盖块（一个字符不会被重复或部分遮盖）。
3. 发布成功后跳转到「发布记录」页（`/publications`），其中的公开链接形如 `/p/<随机令牌>`，可直接在浏览器打开。公开页**只含脱敏文字**，没有任何原件、附件或档案站内入口，并带 `Cache-Control: no-store` 与 `noindex`。
4. 规则：
   - **词表为空不得发布**：发布按钮禁用，接口同样拒绝。
   - **有效改动才升版本**：提交内容与现有词表完全相同（仅顺序/空白不同）视为无改动，版本号与既有公开页不变；新增、删除或替换词条才会让版本号 +1。
   - **词表有效改动后旧发布页立即失效**：访问旧链接返回 HTTP 410 且不展示任何脱敏文字，需按新词表重新发布；重发会更换链接令牌，旧令牌变为 404。
   - 改词表、发布与公开页访问交错时，公开页只可能展示**当前词表**对应的完整遮盖结果；发布过程中词表被替换会整笔拒写并按新词表自动重试。
   - 任何一步写入失败都在单事务内回滚，此前可用的词表与公开页保持不变；原档浏览与附件下载始终照常可用。

## 一致性规则

采集流程先读元数据、下载附件、再读一次元数据，并要求：

- 两次读到的修订号、正文、附件描述、撤稿状态完全一致（防止采集中途站点改稿）；
- 正文修订号与附件修订号相同；否则整次拒收；
- 附件实际字节长度与 SHA-256 与源站声明一致；否则整次拒收。

与档案比对时：

| 情况 | 行为 |
| --- | --- |
| 修订号更新 | 新增一个存档版本（正文 + 附件同事务写入） |
| 修订号相同、内容一致 | 不重复建版（`unchanged`） |
| 修订号相同、内容不同 | 报告源站冲突（`conflict`），不覆盖旧版 |
| 修订号回退 | 报告冲突，不创建、不覆盖 |
| 同号仅撤稿状态变化 | 更新公告级撤稿标记，不新建版本 |

**不可变与原子性**：版本行（正文、附件字节与指纹）一经写入不再修改；撤稿状态保存在公告级。每个版本的公告行、版本行、附件 BLOB、日志在同一 `BEGIN IMMEDIATE … COMMIT` 中写入，SQLite 开启 WAL + `synchronous=FULL`。写入失败会回滚；进程在提交前被杀死，重启后只会看到完整旧版或没有新版，不会出现半份版本。

敏感词表替换（删除旧词 + 写入新词 + 版本号 + 日志）与脱敏发布（版本校验 + 发布行 + 日志）同样各自包在单条 `BEGIN IMMEDIATE … COMMIT` 事务中：词表写入失败保留旧词表，发布写入失败保留此前发布页。发布行记录所依据的词表版本号，公开页读取时与全局当前版本号比对，不一致即判定失效（410），因此无需删除历史快照也能保证“只显示当前词表的完整结果”。

## 测试

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

测试覆盖：

- 首次采集、同修订重复采集、改稿、换附件、撤稿/恢复；
- 正文/附件修订不一致整次拒收；
- 同号不同内容冲突且旧版不变；
- 源站修订号回退；
- 附件 SHA-256/长度不符拒收；
- 数据库写入失败回滚、无半份版本；
- 子进程在事务提交前硬退出（模拟进程中断）后重启无残留；
- 档案 Web 页面、下载、错误提示与健康检查；
- 敏感词解析/去重/上限、字面精确匹配、重叠命中合并、标题与正文全覆盖；
- 空词表禁止发布、公开页仅含脱敏文字且无原件入口；
- 词表有效改动升版本并使旧页 410、无改动不升版本、重发换令牌且旧令牌 404；
- 发布途中词表被替换的拒写与按新词表重试；
- 词表/发布写入失败回滚，旧词表与旧公开页保持可用；
- 改词表与发布高并发交错后，外部只能看到当前词表对应的完整结果。

## 源站 API（示范站）

- `GET /api/notices/{公告号}`：公告元数据（含修订号、唯一附件描述）
- `GET /api/notices/{公告号}/attachment?rev=N`：附件字节

档案应用通过 `SOURCE_BASE_URL` 指向该站。若接入其他站点，只需实现相同的元数据字段与附件校验语义。
